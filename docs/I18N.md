# Internationalisation (i18n)

Every user-visible string in the web app comes from a typed message catalog.
English is the only shipped language. The app is ready for translation: adding a
locale means adding one catalog object and changing no components.

## Layout

```
apps/web/src/i18n/
  messages/en/<namespace>.ts   English copy, one flat `as const` object per area
  catalog.ts                   `en` = all namespaces; MessageKey, LocaleMessages types
  runtime.ts                   t(), formatNumber/DateTime/List, LOCALES, active locale
  format.ts                    ICU MessageFormat subset (args, plural, select)
  rich.tsx                     tRich(): messages with inline elements
  pseudo.ts                    en-XA pseudo-locale
  domain.ts                    labels for package enums (categories, ballots, outcomes, USDC amounts …)
  I18nProvider.tsx             locale state, <html lang>, remount on switch
  scanHardcoded.ts             the "no hardcoded copy" scanner (CLI: apps/web/scripts/find-hardcoded.ts)
```

| Namespace | Keys | Covers |
|---|---:|---|
| `common` | 24 | app name, tagline, shared actions, units, mode names |
| `shell` | 316 | shell, landing, lobby, how-to-play, leaderboard, settings, mode pages, platform (ledger, World ID) |
| `ds` | 35 | design-system defaults (Field, Countdown, Receipt, Toast, States …) |
| `trial` | 119 | trial frame, view toggle, walk sandbox, roaming-courtroom HUD |
| `solo` | 366 | Solo filing, trial, jury, verdict, share card; classic stage |
| `versus` | 467 | Versus case room, briefing, jury, verdict, receipts |
| `grandJury` | 389 | docket, case page, funding, juror duty, gallery, pricing |
| `domain` | 158 | display labels for enums owned by `packages/*` |
| **total** | **1874** | |

## Using it

```tsx
import { t, tRich, formatNumber } from '@/i18n';
import { formatAmount, categoryLabel } from '@/i18n/domain';

<h1>{t('solo.file.title')}</h1>
<p>{t('versus.invite.waiting', { count })}</p>                 // '{count, plural, one {# invite} other {# invites}} waiting'
<p>{tRich('grandJury.feed.hash', { code: (c) => <code>{c}</code> }, { hash })}</p>  // '… <code>{hash}</code>'
<Amount>{formatAmount(usdc)}</Amount>
```

- **Keys are typed.** A key that does not exist fails `tsc`.
- **Syntax.** `{name}` interpolation, `{n, plural, =0 {…} one {# …} other {…}}`, and
  `{x, select, a {…} other {…}}`. Copy cannot contain any other braces.
- **Call `t()` only at render time,** or in handlers and functions. Never call it at
  module top level, because that freezes one locale. Copy tables hold `MessageKey`s
  and are translated where they render. For example, `NAV_ITEMS[].labelKey`,
  `MODE_PRESENTATION`, and the registry `label` getters.
- **Numbers, dates and lists** go through `formatNumber`, `formatDateTime` and
  `formatList`. USDC amounts go through `formatAmount` and are formatted from exact
  decimal strings, so they never round through a float.
- **Package enums stay English in `packages/*`.** Other packages and their tests use
  those English values. The web layer maps each id to a `domain.*` key. Case content
  is data and is not translated: titles, stories, AI dialogue and demo seeds.
- **The roaming courtroom** lives in `@cringe-court/scene`, which cannot import the
  app. It exports `RoamStrings` and `DEFAULT_ROAM_STRINGS`, and
  `<RoamCourtroom strings>` takes overrides. `src/trial/roamStrings.tsx` builds
  them from the `trial` namespace.
- **Escape hatch.** For text that is genuinely not translatable, such as the
  CRINGECOURT wordmark or a pause glyph, put `i18n-ignore` in a comment on that
  line or the line above it. Use it sparingly.

## Adding a locale

1. Add a `LocaleMessages` object (same namespaces and keys, translated) and register
   it in `runtime.ts` (`LOCALES`, `catalogs`, `intlTag`).
2. Add it to the Settings → Language choices.
3. Run the checks below. Text grows: the pseudo-locale already pads copy by about 35 %.

The locale is chosen from `?locale=` first, then the stored choice in
`localStorage['cc:locale']`, then English. Switching the locale remounts the
tree, so every `t()` re-renders. Unsaved in-page state is lost, which is
acceptable for a rare action.

## Proof (tests)

- `src/i18n/catalog.test.ts`:
  - Every message parses and formats with its own arguments.
  - Every message pseudo-localises without losing arguments.
  - No key is unused.
  - The scanner finds **0** hardcoded strings in `apps/web/src` TSX. It checks
    JSX text, string children, and text props (aria-label, title, placeholder,
    alt, label, *Label …). Tests and `gallery/` are exempt; the gallery is a
    design-system specimen page.
- `src/i18n/pseudoRender.test.tsx` renders 17 real routes in `en-XA`. Every catalog
  message comes out wrapped in ⟦…⟧ and accented, and the test fails on any
  perceivable English left on screen. Demo-docket case content and hashes are
  exempt as data.
- Manual check: open any page with `?locale=en-XA`, or pick
  **Settings → Language → Pseudo-locale (testing)**.

## Known gaps

- Some prose is composed inside the domain packages and is shown as-is:
  - Grand Jury share-card headlines and log lines.
  - Solo `summary.headline` and `shareText`.
  - Versus briefing questions and issue messages.
  - `ActionResult` error strings (they have no error codes).
  - Some receipt line labels.

  None of these appear on the 17 routes the pseudo-locale test renders (they
  surface inside flows). Moving them to codes plus catalog keys is a package-level
  change.
- In-world roam content (NPC lines, interaction prompts, callouts) comes from the
  scene's game scripts and needs a content-localisation pass.
- Right-to-left layouts have not been audited. CSS mostly uses logical
  properties, but not everywhere.
